# Yuzuha v0.1.11 recovery

Status: Published on 2026-08-25. API 35 emulator package smoke passed; the
legacy `0.1.8` to `0.1.11` live-feed transition and physical Pixel remain
unverified.

## Purpose

Published bundle `0.1.10` requires native `0.1.9`, so native `0.1.3` devices on bundle `0.1.8` reject the global latest pointer. `0.1.11` restores a signed bundle compatible with native `0.1.3` and explains the one-time native bootstrap without calling bridges absent from that shell.

Every release version must also have an APK. The prepared `0.1.11` APK uses the legacy native `0.1.3` capability boundary, embeds the exact bundle `0.1.11`, uses Android version code `6`, and retains the production signer. It does not pretend the legacy shell can securely automate APK installation.

## Open gates

- Prove native `0.1.3` with bundle `0.1.8` accepts and launches OTA `0.1.11`.
- Prove the settings link opens the immutable latest release page without claiming the APK was verified by the legacy shell.
- Publish the APK, bundle, native metadata, and legacy `bundle.json`, then preserve that pointer on every later latest release while native `0.1.3` remains supported.

The release keeps app schema 33 and repository schema 3. Native `0.1.3` cannot gain the new APK verifier, FileProvider path, manifest permission, archive inspection, or bounded root runner through OTA.
