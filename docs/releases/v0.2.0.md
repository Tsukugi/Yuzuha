# Yuzuha v0.2.0 native updater baseline

Status: Published on 2026-08-25. API 35 emulator installer gates passed;
physical Pixel validation remains open.

## Release contract

`0.2.0` starts a new native compatibility line and introduces signed automatic APK updates. Every later `0.2.x` version must publish both a complete APK and a bundle. Installed `0.2.x` devices prefer same-line OTA; when a later line is current, they download and install that latest patch APK directly.

The Android application ID is `dev.yuzuha`, version name is `0.2.0`, and version code is `7`. The embedded bundle and `bundle-0.2.json` baseline are `0.2.0`. `android-update.json` is the separate latest-APK record.

## Implemented checks

- Ed25519 manifest signature and immutable HTTPS URL.
- Bounded size and exact SHA-256.
- APK package, version name, increasing version code, and installed signer certificate.
- App-private download and deterministic cleanup.
- Bounded Magisk/AOSP uid-0 probes and fixed `pm install -r` root path.
- One read-only FileProvider grant to Android's installer when root is unavailable.
- No fallback to a second installer after an ambiguous root-install failure.
- Bundled Bouncy Castle Ed25519 verification for Android API 35, whose platform providers do not expose a software Ed25519 key factory.

## Open gates

- Install over the signed production package on a physical Pixel and prove workspace preservation there.
- Validate the live-feed transition on a physical device still running native `0.1.3`.
- Published APK, bundle, both signed metadata assets, and the preserved legacy `bundle.json` pointer together.

The release keeps app schema 33 and repository schema 3. No account, sync, polling worker, or background update service is added.

## Device evidence

- A production-data API 35 emulator upgraded through signed `0.1.11` and `0.2.0`; a note created before the second install remained exactly once afterward.
- The production FileProvider installer opened Android-owned install/security UI on a non-root API 35 Play image.
- A disposable API 35 userdebug AVD with a controlled test-only root service upgraded production `0.1.11` to `0.2.0`, version code `7`, through the production root installer without system UI. Unit tests separately prove Magisk and AOSP command dialects. This is not a claim that every third-party root manager was tested.
